## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-038). Primary owner role: Profile agent.

- Problem: Avatar camera/gallery choices are placeholders.
- Impact: Preset assets are reported as actual uploads.
- Implement: Implement image picker, durable upload and actual preview with cancel/error handling.
- Acceptance: Chosen gallery/camera image persists across restart; cancel does not report success.
- Starting point: [source](../../../lib/features/profile/presentation/profile_screen.dart).

## Implemented

Current result (2026-11-01T12:38:25.993Z): Gallery/camera now invoke the real image picker instead of assigning a preset and announcing an upload. Cancellation leaves the sheet open without success feedback. Images are decoded and canonicalized to bounded PNGs, previewed as actual bytes and retained in account-scoped encrypted storage before transport. A restart restores the immutable object path and owned bytes; upload/profile failures keep the selected image for retry and saving closes only after profile acknowledgment. Preset/removal also await persistence. Current profile photos download from a private bucket with session guards, old images clear on reference changes, and failed reads offer retry. Additive Storage policies restrict uploads to exact owner UUID PNG paths, deny object mutation, and share only the current reference with accepted friends/active tab peers. Profile references require the owned object to exist first; arbitrary external URLs are not rendered.

## Remaining and unverified

SQL Storage policies are tested locally; real Supabase upload/download HTTP, response-loss/duplicate responses and two-device persistence remain unverified. Existing external OAuth avatar URLs render initials rather than external image requests. No migration deployed or release approval.
