## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-025). Primary owner role: Security agent.

- Problem: PIN verification has no throttling.
- Impact: Repeated guessing is unrestricted and verifier derivation is too cheap.
- Implement: Use a versioned slow salted verifier; persist failed attempts, delay after five failures, and provide reauthenticated reset.
- Acceptance: Delay survives restart; correct PIN unlocks; legacy verifier upgrades only after successful verification.
- Starting point: [source](../../../lib/core/services/pin_protection_service.dart).

## Implemented

Current result (2026-10-31T14:04:21.021Z): Versioned PBKDF2-HMAC-SHA256 verifier uses 600,000 iterations, 128-bit random salt and 256-bit output through cryptography 2.9.0. Native derivation runs in a worker isolate. One atomic secure-storage JSON record holds verifier and reserved attempts; five failures trigger a persisted 30-second delay, increasing to 15 minutes. Attempts serialize across service instances. Correct legacy verification upgrades only after success. Corrupt/partial records fail closed. Lock UI reports delay and offers fresh device-authenticated PIN recovery; changing/removing existing PIN also requires fresh platform biometric/device credential and current session.
