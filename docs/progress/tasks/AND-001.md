## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-041). Primary owner role: Platform/release agent.

- Problem: Android scheduled notification integration is incomplete.
- Impact: Missing receivers and exact-alarm access can prevent reminders.
- Implement: Add required receivers/reboot integration, request special access where needed and use an inexact fallback when denied.
- Acceptance: Scheduled reminder fires with permission allowed/denied fallback and survives reboot appropriately.
- Starting point: [source](../../../android/app/src/main/AndroidManifest.xml).

## Implemented

Completed source integration: explicit opt-in, private scheduled/reboot receivers, denied/revoked exact-access fallback, account-scoped preferences and stable IDs. Resume now rechecks in-memory due reminders and includes current alarm-access policy in deduplication, so a persisted plugin request cannot suppress rearming after special-access changes. Account/session changes and cancellation discard rechecks.

## Remaining and unverified

Emulator behavioral acceptance (2026-11-04): exact reminder alarm survived `adb reboot`; boot receiver re-armed it and Android displayed the scheduled notification. With the actual Alarms & reminders setting disabled, the inexact alarm fallback also delivered. Notification permission denial, taps/deep links, package replacement, OEM battery behavior and physical-device behavior remain unverified; status stays implemented.
