## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-022). Primary owner role: Payments/backend agent.

- Problem: Concurrent confirmations may overpay.
- Impact: Separate pending rows can pass the balance check together.
- Implement: Lock the obligation pair before rechecking and confirming; make duplicate confirmation idempotent.
- Acceptance: Concurrent confirmations whose sum exceeds debt cannot both succeed; exact debt never becomes overpaid.
- Starting point: [source](../../../supabase/migrations/20261029000001_atomic_money_contract.sql).

## Implemented

Current result (2026-10-31T18:09:20.800Z): Payment decision RPC obtains the shared tab obligation lock before the row lock and balance read. Concurrent different submissions recheck current pair outstanding after acquiring the lock; overpayment is rejected. Repeated same-ID confirmation and identical rejection are idempotent; different decisions/reasons conflict. Native race tests use independent backend sessions and an injected delayed UPDATE to make the old race reproducible.
