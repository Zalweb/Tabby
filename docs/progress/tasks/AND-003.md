## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-043). Primary owner role: Platform/release agent.

- Problem: Picker recovery and draft/back protection are missing.
- Impact: Process recreation and system back can lose user input.
- Implement: Handle retrieveLostData, store drafts and implement PopScope for multistep entry and unsaved edits.
- Acceptance: Kill/recreate during picker, recover image/draft; back returns a step or asks before discarding edits.
- Starting point: [source](../../../lib/core/services/receipt_attachment_service.dart).

## Implemented

Current result (2026-11-01T14:47:35.835Z): Added startup image_picker retrieveLostData with encrypted owner/workflow/request attribution before launch, owned result bytes before return, bounded images, cancellation/error handling, same-result write retry and compare-ID acknowledgment. Unattributed results never guess an account. Expense, payment, receiving-method and profile-edit drafts persist account-scoped fields; avatar and receipt workflows accept recovered images through durable handoff. Back returns an expense step or offers keep/edit/discard; discard also removes its recovered image. Financial form attempts freeze their intent and reuse stable operation IDs, with local/acknowledged replay guards including cash already at zero balance. Payment proof no longer references a temporary file. Exact draft routes close on session changes without popping replacement routes. Existing Android singleTop/plugin lifecycle configuration retained; no unnecessary native override added.
