## Scope and acceptance

The three first-launch pages follow a horizontal drag in either direction. The indicator stretches continuously during the transition and resolves to one selected page when settled. Next advances on the first two pages. Get started acknowledges the tour on the third and goes to the existing Google sign-in. Keep Back, Skip, repair of a failed preference write, reduced motion, keyboard and accessibility access, and readable content at 200% text in short viewports.

## Implementation plan

- Use a Flutter page controller shared by direct gestures and step buttons. Keep the active step, accessible announcement and primary button in sync when a page settles.
- Interpolate the indicator edges from fractional scroll position. Use existing Tabby palette roles and keep the navigation controls reachable while each page scrolls vertically if needed.
- Check movement before finger release, both drag directions, button/back navigation, last-page acknowledgment, indicator contrast, and short and large-text layouts.
- Review and push a scoped branch based on the existing first-launch review. Verify and install a signed tablet candidate only after coordinating the preceding QA-053 build and device slot. Preserve the latest verified runtime and existing tablet data.
