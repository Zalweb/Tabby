## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-018). Primary owner role: Payments agent.

- Problem: QR validation, same-phone use and profile visibility are incomplete.
- Impact: An arbitrary image can be saved and payers cannot easily import receiving QR into a wallet.
- Implement: Validate readable QR, retain quiet zone, add fullscreen/save/share and authorized friend-profile access.
- Acceptance: Wallet import works on one phone; unreadable images fail; friend/debtor access matches the agreed matrix.
- Starting point: [source](../../../lib/features/payment_methods/presentation/payment_method_payment_sheet.dart).

## Implemented

Current result (2026-10-31T19:14:45.701Z): Receiving QR supports fullscreen zoom, Android Save QR image via system document creation and Share QR image via a narrow read-only FileProvider URI. Export downloads the active private object under current row/storage authorization and validates a readable PNG before invoking Android. Session changes discard pending bytes. Save cancellation/error is distinct from success; sharing acknowledges chooser launch only. Accepted-friend options open read-only receiving methods with refresh/revocation handling. Readability/crop equivalence is implemented by QR-001, and owner/friend/actual debtor authorization by QR-002.
