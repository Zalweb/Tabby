## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-011). Primary owner role: Ledger/UI agent.

- Problem: Malformed currency is accepted or throws without feedback.
- Impact: Invalid text can turn into a smaller valid amount or break submission.
- Implement: Validate complete decimal input and catch parsing errors inline; accept PHP up to 999999999.99, maximum two decimals, no exponent or malformed grouping.
- Acceptance: Reject abc.50, 1.234, exponent and overflow input; accept valid formatted PHP exactly.
- Starting point: [source](../../../lib/core/utils/currency_formatter.dart).

## Implemented

Current result (2026-10-31T14:25:55.961Z): PHP parser validates the entire decimal/grouping syntax and converts through BigInt to exact integer centavos. Malformed prefixes, exponents, excess decimals, bad grouping and overflow cannot become smaller amounts. App validation and source database constraints enforce maximum PHP 999,999,999.99. Expense/payment forms show inline errors without throwing; quick-add chips reject malformed/overflow input. Constraints use NOT VALID to retain historical rows for explicit review.
