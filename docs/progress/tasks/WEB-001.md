## Scope and acceptance

Refresh the public Tabby landing page so it reflects the current warm app and current release, using `https://www.tarsi.cloud/` only as a structural and visual reference. The page must not invent reviews, user counts, awards, press coverage, ratings, or unrelated product claims.

Accepted outcomes:

- Tarsi-like structure: sticky header, hero with inline title pill, rotated phone, floating mascot, three feature cards, screenshot marquee, stats and principles, offline walkthrough, Q&A cards, dark download/release card, community card and dark footer.
- Authentic Tabby copy only: friendship-first running tabs, integer-centavo custom splits, GCash/Maya/QR Ph settlement with recipient confirmation, append-only ledger, offline-durable queue, reminders, group tabs, encrypted payment details, and no money held or moved by Tabby.
- Current mascot artwork and current app screenshots; no emoji and no user-facing “GitHub” link text.
- Download engine keeps release-aware APK/IPA links, version/date/size/status/changelog data roles, canonical fallbacks, escaping and cache behavior.
- `landing/` and `docs/` remain byte-identical for pages and shared assets; legal pages keep their layout and current branding.
- Responsive layout has no horizontal overflow, navigation remains usable, FAQ/release disclosures work natively, and release notes render as safe HTML.

## Implemented

- Replaced the prior dark/amber single-page layout with a 1080px warm cream design: Inter typography, ink/charcoal surfaces, 28px card radii, sticky glass header, mobile navigation panel, hero with “Keep tabs. / Settle up.” pill, rotated phone, floating mascot and proof chips.
- Added the current content structure: three feature cards backed by the current mascot situation artwork, a six-screen light/dark marquee, “Why Tabby” stats and six principles, offline how-it-works panel, eight FAQ cards, a dark download/release card with build metadata, community settlement chips, and a four-column footer.
- Preserved and extended the release engine in `landing/app.js`: latest GitHub release fetch, five-minute cache, escape-first markdown rendering, version/date/APK/IPA sizes, APK filename, live status, APK and IPA canonical fallbacks, and safe changelog HTML. Added `ipa-download-btn` and `ipa-size` surfaces.
- Added current marketing assets: launcher icon, seven situation mascots and six current light/dark app screenshots. Captures were produced from the current Flutter widgets with a synthetic Maria Santos fixture and loaded Inter font; the profile screenshot was excluded because it still contains a placeholder Tabby ID.
- Updated legal pages (`privacy.html`, `terms.html`) to the current launcher branding and section navigation while retaining their dark legal hero, cards and inline layout. Added compatible shared button/header/footer styles.
- Rewrote `test/web_landing_test.js` for the new contract, including strict landing/docs mirror checks, asset mirror checks, content/emoji/“GitHub”-label assertions, release-data simulation, and the live Vercel shell probe. Removed retired landing-specific tests.
- Retired the old preview/icon assets and synced all changed pages, styles, scripts, mascots, screenshots and launcher assets into `docs/`.
- Fixed three issues found in browser review: the hero glow no longer forces horizontal overflow (it previously expanded mobile layout to 551px), the header navigation stays on one row with the tagged hero layout (960px mobile breakpoint), and the marquee screenshots load eagerly so duplicated track frames never appear blank.
