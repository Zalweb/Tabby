## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-045). Primary owner role: Platform/release agent.

- Problem: Automatic release can publish a debug-signed APK.
- Impact: Public updates may have the wrong signing identity.
- Implement: Require release signing on every publishable path; verify certificate and exact candidate digest before upload; test upgrade and 16 KB native compatibility.
- Acceptance: Main/tag/manual publication cannot upload debug APK; installed prior release upgrades preserving data and OAuth works.
- Starting point: [source](../../../.github/workflows/publish-latest-build.yml).

## Implemented

Current result (2026-10-31T19:25:40.018Z): Removed Gradle debug-signing fallback and made every app release task require real signing configuration. Build/main/tag workflows now produce private artifacts only; Android and unsigned iOS direct publication paths are removed. Manual Android publication is centralized on main behind android-release environment and exact build-run provenance. Both artifact upload and publication verify configured certificate identity, signature, package/version, nondebuggable manifest, APK digest and ZIP/ELF 16 KB alignment. Publication also requires reviewed exact-artifact evidence, completed M1/QA/REL tasks, documentation-only descendants and explicit recorded release authorization.
