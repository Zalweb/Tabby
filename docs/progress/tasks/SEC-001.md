## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-023). Primary owner role: Security agent.

- Problem: Cold-launch lock bypass and PIN navigator failure.
- Impact: Private ledger starts visible; PIN unlock dialog cannot open.
- Implement: Load security state before sensitive content; lock at cold start and use a valid navigator or inline unlock route.
- Acceptance: Cold launch is protected; PIN dialog opens on resume; cancellation leaves lock active.
- Starting point: [source](../../../lib/core/widgets/biometric_gate.dart).

Current result (2026-10-31T13:57:53.389Z): Security settings expose explicit readiness and fail closed on storage errors. Sensitive descendants are not mounted before readiness or cold-start unlock. Security preferences are account scoped. The above-router lock has its own navigator/overlay for PIN entry; cancellation stays locked, and resume honors auto-lock.
