## Scope and acceptance

Release `v1.0.4+24` is live and the landing script rewrites every download field from the GitHub API after load. The remaining defect is the static fallback served in the HTML and the script defaults: without JavaScript, or before the API call resolves, the page still names `v1.0.3`, `Tabby-v1.0.3.apk`, `74.8 MB` and `September 19, 2026`. Acceptance: both mirrored copies (`landing/` and `docs/`) carry the current release values, the live rendered page shows `v1.0.4+24`, and the APK/IPA buttons resolve to the published assets.

## Implemented

- Replaced the static fallback in `docs/index.html` and `landing/index.html` (identical mirrors): all six version pills and the download-hub version now read `v1.0.4+24`, the filename reads `Tabby-v1.0.4+24.apk`, the size reads `70.2 MB` (73,609,244 bytes) and the date reads `November 18, 2026`.
- Replaced the script defaults in both `docs/app.js` and `landing/app.js`: tag fallback `v1.0.4+24`, size fallbacks `70.2 MB`, date fallbacks `November 18, 2026`. Release-application logic is unchanged.
- Verified the change with `node test/web_landing_test.js`, including its strict `landing/`↔`docs/` mirror equality assertions, and rendered the live site in headless Chromium to confirm the release engine still applies `v1.0.4+24` and points each button at the versioned assets.
