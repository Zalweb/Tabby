## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-026). Primary owner role: Security agent.

- Problem: Old account loads can commit after session change.
- Impact: Late asynchronous responses can repopulate another session with stale data.
- Implement: Scope requests/provider caches by account plus session generation and discard late results.
- Acceptance: Delay account A response, logout/login B, then release A response; no A data is rendered or cached as B.
- Starting point: [source](../../../lib/features/tabs/application/tabby_providers.dart).

## Implemented

Current result (2026-11-01T13:24:07.002Z): Dated superseding fix for the SDK boundary: profile email and recovery-password updates use a captured account/session/JWT HTTP transport that never installs its response into the shared GoTrue session or emits userUpdated. It verifies the token subject/expected returned actor and discards obsolete acknowledgments, including same-account relogin and timeout. SDK and email mutation share one serialized PKCE adapter over the existing verifier namespace; queued stale writers are rejected and newer verifier writes remain last. Core/social RPC expected-owner checks and previous account-scoped queues/caches remain. No direct shared-SDK updateUser call remains in application code.
