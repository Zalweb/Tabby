## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-044). Primary owner role: Platform/release agent.

- Problem: History loading and cache rewriting will scale poorly.
- Impact: Sequential RPCs, scans and full JSON rewrites can stall large histories.
- Implement: Batch balances, page history, reconcile by IDs and migrate cache/queue to transactional Drift storage with keys kept in secure storage; benchmark before selecting encryption integration.
- Acceptance: Profile 100 tabs/10000 entries on low-memory Android; page rendering remains responsive and queue survives interrupted migration.
- Starting point: [source](../../../lib/features/tabs/data/tabby_local_cache.dart).

## Implemented

Integrated the preserved native encrypted Drift cache/queue: secure-storage key, fail-closed SQLite3MC capability check, background executor, atomic legacy import/authority marker, ID-based incremental row writes, durable queue IDs and deletion tombstones. Added authenticated bounded ledger-read RPCs and indexes, UUID-paged headers/history and one balance batch per 100 tabs. Loader validates scope, IDs, cursor progress, bounds and complete balances before publication; failures preserve the existing cached ledger. Complete history remains available for group obligations. Tab detail reveals 50 records at a time. JSON encoding and tab decoding run off the UI isolate in production; widget tests explicitly use an inline codec with mocked platform storage.

## Remaining and unverified

Emulator behavioral acceptance (2026-11-04): seeded 100 tabs/10,000 synthetic in-memory entries and rendered 100-row history for one tab. Runs measured 147/184 ms seed, 1,341/1,688 ms first-page render/settle, and 402/346 ms reveal of older 50. This is not a low-memory/database/frame benchmark. AVD RAM was 4,005,308 kB total / 2,060,740 kB available; PAGE_SIZE=4096, so 16 KB compatibility remains open; status stays implemented.
