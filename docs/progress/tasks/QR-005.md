## Scope and acceptance

[Audit finding](../../audits/2026-10-31-android-review.md#aud-20261031-017). Primary owner role: Payments agent.

- Problem: Preferred method and removal state are wrong.
- Impact: Adding clears local preference and deleting can leave the removed method visible.
- Implement: Make preference promotion atomic and update remaining list before selecting a successor.
- Acceptance: Add nondefault preserves preference; remove default promotes exactly one remaining method.
- Starting point: [source](../../../lib/features/payment_methods/application/payment_methods_provider.dart).

## Implemented

Current result (2026-10-31T19:00:30.663Z): Moved save/prefer/remove to one server transaction serialized per owner. First active method becomes preferred; nondefault creation preserves preference; removal soft-deactivates the method and promotes exactly one remaining method atomically. Client removes acknowledged deleted methods before loading the authoritative successor, never issuing a separate promotion from a stale list. Direct client method mutations are revoked. Metadata revision snapshots retain changes.
