## Scope and acceptance

M2 capability expansion. Primary owner role: Feature agent.

- Problem: Acknowledgment, proposals and disputes.
- Impact: Users cannot review or contest an obligation through a complete workflow.
- Implement: Add pending acknowledgment, proposal acceptance/rejection and dispute resolution; preserve original amounts and record approved adjustments append-only.
- Acceptance: Unauthorized users cannot accept; concurrent decisions resolve once; rejected proposals never change balances.
- Starting point: [source](../../../lib/features/tabs/domain/models.dart).

## Implemented

Checkpoint implementation verified and the dispute-resolution acceptance path completed. Acknowledgment is an immutable transaction/registered-party attestation, excludes creator self-acknowledgment and is never derived from transaction status or participant acknowledged flags. Proposals route through CAP-006's frozen reviewer approval; rejection does not append financial rows. Disputes and resolution votes use separate additive tables, preserve the original transaction/status/balance, and require explicit approval from every frozen registered party. A rejected resolution leaves its dispute open; a later proposal can be accepted. This workflow records agreement text only; a financial correction still uses the separate CAP-006 workflow. The review UI and all M2 capabilities remain gated off.

The review projection includes recent proposal/dispute summaries and bounded cursor history. A new Flutter regression exercises the visible dispute-resolution action and confirms that the explicit vote and exact resource IDs are durably queued.
